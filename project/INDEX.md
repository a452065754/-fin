## 工作流程（重要）

本项目要求**每个功能完成后立刻更新知识库**，不要攒到最后。标准流程：

```
1. 实现功能
2. 跑测试，确认全绿
3. 更新 STATUS.md      —— 把这个功能加进「已支持」
4. 更新 ROADMAP.md     —— 勾掉对应任务，状态改为 ✅
5. 追加 PROGRESS.md    —— 记录：做了什么 / 怎么验证的 / 提交号
6. 追加 LESSONS.md     —— 记录过程中踩的坑（没有就跳过）
7. 追加 SKILLS.md      —— 沉淀出可复用方法时（没有就跳过）
8. 提交并推送
9. 跑 tools/verify_docs.py 确认文档没写错
```

**为什么这么严格**：交接过的人都知道，文档最大的问题不是写得少，而是**写完就不更新了**，
三个月后全是错的，比没有文档更糟。所以：

- `PROGRESS.md` / `LESSONS.md` / `SKILLS.md` **只追加，从不删改历史**
  （保留判断演变的轨迹，这比只留结论有用）
- `STATUS.md` / `ROADMAP.md` 是**当前快照**，该覆盖就覆盖
- `tools/verify_docs.py` 会在提交前检查索引链接、状态标记、进度与提交是否一致

## 状态标记规范

全项目统一用这几个标记，脚本会校验：

| 标记 | 含义 |
|---|---|

## 铁律

以下几条是本项目反复踩坑后定下的，**改代码前务必先看**：

1. **测试必须断言数据量** —— 只断言类型会假通过
2. **图表类型分支按特异性排序** —— `heatmap` 含子串 `map`
3. **`Find` 会递归整棵树** —— 拿不准层级时先加 trace 打 print
4. **别改 `toFloat` 语义** —— 公式层共用，图表层加包装函数
5. **`CGO_ENABLED=0` 不能破** —— 破了单文件部署目标就没了
6. **改完模板/静态资源要重启实例** —— 前端有缓存
7. **db.script 的 `"','"` 是 3 个字符** —— 按 2 跳会带出多余单引号
8. **中文连接名在 db.script 的 key 里是 `\uXXXX`** —— 要还原
9. **push 报 credential-manager 缺失是噪音** —— 看 push 结果行
10. **文档里的数字必须脚本比对代码**，不能凭印象写
