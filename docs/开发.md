面向要改代码的人（含 AI 接手）。先读架构，再读每个模块的内部约定。

> **接手第一步**：先读 [project/INDEX.md](../project/INDEX.md)（有 5 分钟上手
> 步骤、项目铁律、工作流程）和本手册第 4 节（关键内部约定）。
>

> 流程见 [project/INDEX.md](../project/INDEX.md) 的「工作流程」。

## 1. 环境

```bash
go version          # 需要 1.22+
export GOCACHE=$(pwd)/.gocache   # 默认 cache 目录不可写时必须指定
export GOPROXY=https://goproxy.cn,direct
```

依赖版本已锁定在 `go.mod`，**不要随意升级**：新版本对 Go 版本要求更高
（如 mysql v1.10+ 要 Go≥1.24、mssql v0.11+ 要 Go≥1.25，本机是 1.22.4）。

```bash
go build ./...
go test ./...        # 需要本机有 FineReport webroot
```

测试依赖 `F:/tomcat-win64/webapps/webroot`。不存在时相关用例会 skip 而非
失败，但**覆盖率会明显下降** —— 改解析层代码前务必确认 webroot 可用。

## 2. 架构

```
cmd/reportviewer/main.go        入口：flag 解析、webroot 探测、HTTP 启动
        │
internal/server/server.go       HTTP 层：路由、路径白名单、模板树扫描
        │
internal/fr/                    解析与渲染核心（无 HTTP 依赖，可独立测试）
  ├── xmlnode.go    通用 XML 树（FineReport 的 schema 高度多态，用泛型树更实用）
  ├── cpt.go        CPT 模板解析（单元格、扩展属性、字典、参数）
  ├── fvs.go        FVS 模板解析（zip + editor.tpl 里的转义 JSON 画布）
  ├── dataset.go    数据集定义与加载（DB / 内置数据）
  ├── connection.go 数据连接发现与 DSN 构造
  ├── embedded.go   内置数据解码（Ascii85 + raw Deflate）
  ├── formula.go    公式求值器
  ├── render.go     CPT 表格渲染（展开、分组、汇总）
  ├── chart.go      图表 XML → 归一化模型
  ├── style.go      样式与单位换算
  └── model.go      对外数据结构（JSON 契约）
        │
web/                            前端（go:embed 打进二进制）
  ├── index.html   页面骨架
  ├── app.js       全部交互 + ECharts 配置
  ├── style.css    样式
  └── vendor/echarts.js   本地 ECharts（离线环境不能走 CDN）
```

**分层原则**：`internal/fr` 不认识 HTTP，只认模板文件和数据集。所有对外
数据结构集中在 `model.go`，前后端契约以它为准。

## 4. 关键内部约定

### 4.1 XML 访问器

`XNode` 提供三种查找，**区别很重要**：

| 方法 | 范围 | 何时用 |
|---|---|---|
| `Child(name)` | 仅直接子节点 | 已知结构层级时（性能好） |
| `ChildAll(name)` | 仅直接子节点，返回全部 | 遍历同级 |
| `Find(name)` | 递归整棵子树 | 结构不确定时 |

> **坑**：`Find` 返回第一个匹配，可能不是你想要的层级。FineReport 大量使用
> 包装节点（`<dataDefinition class="...TableDefinition">`），直接 `Child`
> 往往找不到真正想要的东西。**拿不准就用 `Find`，但要确认命中的是哪一层。**

### 4.2 图表数据定义

这是本项目最容易出错的地方。`ChartDefinition` 下有 **12 种**子节点：

| 定义 | 含义 | 现状 |
|---|---|---|
| `MoreNameCDDefinition` | 分类 × 多指标 | ✅ |
| `OneValueCDDefinition` | 分类 × 单指标 | ✅ |
| `BubbleTableDefinition` | X/Y/半径三轴 | ✅ |
| `CustomDefinition` | 组合图，每系列独立定义 | ✅ |
| `VanGanttTableDefinition` | 起止时间区间 | ✅ |
| `StructureTableDefinition` | 父子层级 | ✅ |
| `VanMapDefinition` / `DillMapDefinition` | 地图 | ✅ |
| `MultiPieValueDefinition` | 多层饼 | 部分 |
| `NormalReportDataDefinition` | 引用报表单元格 | ❌ |
| `MeterTableDefinition` | 仪表盘 | ✅ |
| `MeterReportDefinition` | 仪表盘（引用单元格） | ❌ |
| `BubbleReportDefinition` | 气泡（引用单元格） | ❌ |

**新加一种定义要改三处**：

1. `chart.go` 的类型分发表（`switch` on Plot class）—— 决定 `spec.Kind`
2. `chart.go` 的定义分发表（`switch` on definition name）—— 决定走哪个解析器
3. `chart.go` 的 `decorateSeries` —— 补齐该类型特有的系列字段
4. `web/app.js` 的 `chartOption` —— 加对应渲染分支

### 4.3 图表类型映射

`spec.Kind` 是 ECharts 侧的归一化类型，与 FineReport 的 Plot 类解耦。
Plot 类 → Kind 的映射在 `chart.go` 顶部。

> **坑**：判断用 `strings.Contains(cls, ...)` 时，**必须按特异性排序**。
> 例：`heatmap` 含子串 `map`，若 map 分支在前，热力图会被误判成地图。
> 同类问题还有 `multipie` vs `pie`、`bubble` vs `pie` 等。

### 4.4 组合图的系列图型

FineReport 用 `CustomPlotList` 存每个系列的图型：里面是嵌套的
`VanChartPlot` 节点，class 决定该系列画成柱还是线。顺序与数据列一致。

### 4.5 数据连接

连接配置在 `WEB-INF/embed/finedb/db.script`（**HSQLDB** 文本格式，不是
H2）。表 `FINE_CONF_ENTITY`，键 `ConnectionConfig.connections.<名字>.<字段>`。

> **三个解析坑**（都踩过）：
> 1. INSERT 语句是 `VALUES('key','value')`，分隔符 `"','"` 是 **3 个字符**，
>    `rest[q+2:]` 会把值前面的单引号带上。
> 2. 中文连接名在 key 里是 `\uXXXX` 转义，必须先还原才能按名字匹配。
> 3. SQL 字面量内 `''` 是转义单引号。

口令**不读 FineReport 的加密存储**，改用环境变量 `FINE_PWD_<连接名>`。

### 4.6 数值转换

`toFloat` 只认数字类型。日期列在模板里是**字符串**（如
`2015-01-06 00:00:00`），需要用 `toFloatOrDate`（转天数）。

> **不要改 `toFloat` 的语义** —— 它被公式求值器共用，语义变了会波及
> 整个公式层。图表层加包装函数即可。

## 5. 加一个新图表类型的完整流程

以「加一个词云」为例：

```bash
# 1. 后端：类型映射
#    internal/fr/chart.go → switch on Plot class
case strings.Contains(cls, "wordcloud"):
    spec.Kind = "wordcloud"

# 2. 后端：数据定义解析（若该类型用新的定义结构）
#    internal/fr/chart.go → switch on definition name

# 3. 后端：系列字段补齐
#    internal/fr/chart.go → decorateSeries

# 4. 前端：渲染分支
#    web/app.js → chartOption()

# 5. 测试：找真实模板，断言类型 + 数据量
#    internal/fr/chart_test.go
```

## 6. 写测试的规矩

**这是本项目踩过坑的地方，务必遵守。**

### 6.1 必须断言数据量，不能只断言类型

```go
// ✗ 假通过：series=0 也会 PASS
c := firstChartOfKind(t, "xxx.cpt", "gantt")
if c.Kind != "gantt" { t.Error("类型不对") }

// ✓ 必须确认真的取到数据
if len(c.Series) == 0 { t.Fatal("甘特图没有数据系列") }
total := 0
for _, s := range c.Series { total += len(s.Data) }
if total == 0 { t.Fatal("甘特图系列没有数据点") }
```

之前 combo/gantt/structure 三个用例因为只断言类型，空数据也 PASS，
白排查了一轮。

### 6.2 数据为空是合法情况时要显式说明

某些模板的内置数据本身就解不出来（Ascii85 截断），这时要断言**解析行为**
而不是数据量，并写清原因：

```go
if len(ds.Rows) == 0 {
    t.Log("内置数据为空（Ascii85/Deflate 解码截断），本次只验证类型识别")
}
```

## 7. 调试技巧

### 7.1 加临时追踪

复杂 XML 层级用 print 定位最快：

```go
fmt.Printf("[trace] inner=<%s> children=%d\n", inner.Name, len(inner.Children))
for _, n := range def.Children {
    fmt.Printf("[trace]   child <%s> td=%v\n", n.Name, n.Child("TableData") != nil)
}
```

**定位完务必删掉**（提交前 `grep -rn "trace"` 检查）。

### 7.2 扫真实模板统计覆盖面

```bash
# 图表类型分布
grep -rhoP '<Plot class="[^"]*"' --include="*.cpt" . | sed 's/.*class="//;s/"//' | sort | uniq -c | sort -rn

# 数据定义分布
grep -rhoP '<ChartDefinition>\s*<(\w+)' --include="*.cpt" . | sed 's/.*<//' | sort | uniq -c | sort -rn
```

### 7.3 起服务实测

```bash
export GOCACHE=$(pwd)/.gocache
go build -o bin/reportviewer.exe ./cmd/reportviewer
./bin/reportviewer.exe -addr 127.0.0.1:8099 &

curl -s "http://127.0.0.1:8099/api/preview?path=xxx.cpt" | python -m json.tool
```

看 `X-Render-Ms` 响应头知道渲染耗时。

### 7.4 前端验证

`web/vendor/echarts.js` 是本地副本，改图表配置后用浏览器控制台看
`chartOption(spec)` 的返回值。**注意**：改完模板或静态资源要**重启实例**
才加载新版（前端有缓存），否则看到的是旧 HTML。

### 7.5 和 FineReport 原始实现做基准对照

解析结果和 FineReport 对不上时，**不要继续猜参数** —— 它的 class 文件就在
`WEB-INF/lib` 里，直接反汇编 + 当库调用做 ground truth：

```bash
cd /tmp && mkdir oracle && cd oracle
unzip -o -q /f/tomcat-win64/webapps/webroot/WEB-INF/lib/fine-cbb-11.0.jar \
    "com/fr/stable/Ascii85*"
javap -c -p com/fr/stable/Ascii85InputStream.class   # 看字节码
```

项目里已备好基准工具 `tools/oracle/Ascii85Oracle.java`：

```bash
# 编译（class 需放在 com/fr/stable/ 下）
javac -encoding UTF-8 -cp . -d . tools/oracle/Ascii85Oracle.java
# 逐条比对：自己的解码结果 vs Java 原版
java -cp . Ascii85Oracle < payloads.txt > oracle.txt
```

**当前结论**：内置数据的 Ascii85 解码与 FineReport 原版 **718/718 条载荷
字节级完全一致**。剩下的解码失败是**模板文件自身的数据问题**，不是解码器
问题（见 [project/LESSONS.md](../project/LESSONS.md) A6 与 D4）。

## 8. 代码风格约定

- 注释解释**为什么**，不复述代码在做什么
- 中文注释与中文错误信息（面向国内实施人员）
- 错误信息要**可操作**：指明是哪个连接、该设哪个环境变量
- 新增功能同步更新 `README.md` 的能力表和本文档
- 提交信息写清楚「改了什么 + 为什么 + 顺手修了哪些 bug」

