# 部署手册

面向运维/实施人员。目标是让一个不了解本项目的人，照着本文能独立完成安装、
配置与验证。

## 1. 运行前提

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 7+ / Linux（已验证 Windows 10 + PowerShell） |
| 运行时 | **无**。产物是单个 exe，不依赖 Node / Python / JRE / 数据库客户端 |
| 内存 | 常驻约 40–80 MB |
| 磁盘 | exe 约 25 MB |
| 网络 | 需能读取本机 FineReport webroot；需能访问所选数据源（若报表查真实库） |
| Go（仅编译时需要） | 1.22+ |

## 2. 获取产物

### 方式 A：直接用发布产物（推荐给部署方）

从仓库 Releases 下载 `reportviewer.exe`（Windows）或 `reportviewer`（Linux），
放到目标机器任意目录。

### 方式 B：从源码构建

```bash
git clone https://github.com/a452065754/-fin.git
cd -fin
bash tools/build_windows.sh bin/reportviewer.exe
```

**Windows 构建注意**：若默认 build cache 目录不可写（报错
`Access is denied`），先指定一个可写目录：

```bash
export GOCACHE=$(pwd)/.gocache      # Git Bash
set GOCACHE=%CD%\.gocache            # CMD
```

### 杀毒软件误报「HEUR:VirTool/Obfuscator.a」

**现象**：构建过程中 exe 被杀毒软件报毒并删除。

```
病毒名称：HEUR:VirTool/Obfuscator.a
病毒路径：...\AppData\Local\Temp\go-build3804913058\b001\exe\a.out.exe
操作结果：已处理，删除文件
操作进程：C:\Program Files\Go\pkg\tool\windows_amd64\link.exe
```

**这是误报**，不是病毒。Go 链接器产出的 exe 会带一个 `.symtab` 节区，
里面是 `runtime.*`、`go.itab.*` 这类运行时符号名。国内杀软（火绒、360 等）
的启发式引擎把这种「符号表异常丰富的静态链接程序」判成混淆器。

**判别方法**（本项目已验证）：

| 构建方式 | 结果 |
|---|---|
| `go build -o x.exe ./cmd/...` | **被删** |
| `go build -ldflags "-s -w" -o x.exe ./cmd/...` | 正常 |
| 最简单的 hello world Go 程序 | 正常（1.9MB，符号表小） |

关键差别在 `.symtab` 的**有效大小**：未剥离时 85721 字节，剥离后 4 字节。

**解决办法**：用项目自带的构建脚本，它已经带上了正确的链接参数：

```bash
bash tools/build_windows.sh bin/reportviewer.exe
```

脚本会做三件事：

1. `go build -trimpath -ldflags "-s -w"` —— 剥离符号表与调试信息
2. 校验产物的 `.symtab` 是否真的清空（有效大小 ≤ 1KB），不达标就报错
3. 打印产物大小

> 剥离符号表不影响运行，只是丢掉了调试符号。Go 的 panic 堆栈仍然可读。

**如果仍然报毒**（极少数杀软规则更严），在杀软里把该 exe 所在目录
加入信任区即可 —— 它是误报，且本项目是纯 Go 的只读报表查看器，
不含任何下载、注册服务或修改系统的行为。

**`go run` 也会触发**：它在临时目录里链接出 `a.out.exe`，
用完即删，报毒不影响功能，但会刷屏。日常开发用 `go test` 即可，
`go run` 建议配合：

```bash
export GOCACHE=$(pwd)/.gocache   # 避开 %TEMP% 下的临时 exe
```

### 交叉编译 Linux

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o reportviewer ./cmd/reportviewer
```

> CGO 必须为 0。所有数据库驱动都是纯 Go 实现，开启 CGO 会引入
> 对 C 工具链的依赖，破坏「单文件直接扔」的目标。

## 3. 配置

### 3.1 定位 webroot

程序需要 FineReport 的 webroot 目录（里面含 `WEB-INF`）。按以下顺序探测：

1. 环境变量 `FR_WEBROOT`
2. `F:\tomcat-win64\webapps\webroot`
3. `C:\tomcat-win64\webapps\webroot`
4. `D:\tomcat-win64\webapps\webroot`
5. 当前工作目录下的 `webroot/`

都不存在时用第 2 项作为默认值并在启动时报错。**建议显式指定**：

```bash
./reportviewer.exe -webroot "D:\tomcat-win64\webapps\webroot"
```

### 3.2 命令行参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-webroot` | 自动探测 | FineReport webroot 目录（含 WEB-INF） |
| `-reportlets` | `<webroot>/WEB-INF/reportlets` | 模板目录，指向别的目录可只看子集 |
| `-addr` | `:8090` | HTTP 监听地址 |
| `-allow-formula-sql` | 关 | 允许公式里的 `SQL()` 执行查询 |
| `-allow-cross-report` | 关 | 允许公式跨报表取值 |
| `-allow-cross-sheet` | 关 | 允许公式跨工作表引用 |

`FR_WEBROOT` 环境变量与 `-webroot` 等价，命令行参数优先。

### 3.3 安全防护开关

模板是**不可信输入**。有些公式能力会越出「打开这个页面的人」的预期，
这些能力由**安全防护开关**统一控制，**默认全部关闭**。

| 能力 | 开关（环境变量） | 命令行 | 默认 | 说明 |
|---|---|---|---|---|
| 公式内执行 SQL | `RV_ALLOW_FORMULA_SQL=1` | `-allow-formula-sql` | 关 | `SQL("连接名","SELECT ...",行,列)` |
| 跨报表取值 | `RV_ALLOW_CROSS_REPORT=1` | `-allow-cross-report` | 关 | `VALUE("报表名",行,列)` |
| 跨工作表引用 | `RV_ALLOW_CROSS_SHEET=1` | `-allow-cross-sheet` | 关 | `'工作表'!A1` |
| SQL 结果行数上限 | `RV_MAX_SQL_ROWS=2000` | — | 2000 | 超出即截断 |
| SQL 超时秒数 | `RV_MAX_SQL_TIMEOUT=30` | — | 30 | — |

**配置来源与优先级**（从低到高）：

1. 内置默认值（全部关闭）
2. `config.json` 配置文件
3. 环境变量
4. 命令行参数

`config.json` 的查找顺序：`<exe 目录>/config.json` → `<exe 目录>/../config.json`
→ `<工作目录>/config.json`。内容示例：

```json
{
  "formulaSql": false,
  "crossReport": false,
  "crossSheet": false,
  "maxSqlRows": 2000,
  "maxSqlTimeoutSeconds": 30
}
```

**三种开法**（任选其一）：

```bat
:: 1. 命令行
reportviewer.exe -addr :8090 -allow-formula-sql

:: 2. 环境变量
set RV_ALLOW_FORMULA_SQL=1
reportviewer.exe -addr :8090

:: 3. 配置文件（放 exe 同目录）
:: config.json 里写 {"formulaSql": true}
reportviewer.exe -addr :8090
```

**被拦截时的表现**：该单元格显示 `#ERROR`，预览底部的警告面板会写明
「受限能力 SQL() 公式函数 已被安全防护开关关闭（如需开启请设置
RV_ALLOW_FORMULA_SQL=1）」——**明确告诉运维该开哪个开关**。

**当前状态查询**：`GET /api/health` 的 `policy` 字段会返回当前生效的设置：

```json
{
  "policy": {
    "formulaSql": false,
    "crossReport": false,
    "crossSheet": false,
    "maxSqlRows": 2000,
    "maxSqlTimeoutSeconds": 30
  }
}
```

> **内网部署建议**：内网环境如果模板都是自己写的，可以开 `RV_ALLOW_FORMULA_SQL=1`
> 让 `SQL()` 公式正常工作（它只允许 `SELECT`，写操作会被拒绝）。
> 如果这个查看器会暴露给内网以外的人，保持默认关闭。

### 3.4 服务级环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `RV_USER` | 空 | Basic 认证用户名 |
| `RV_PASSWORD` | 空 | Basic 认证口令 |
| `RV_TIMEOUT` | `60s` | 单次渲染的超时上限 |
| `RV_CACHE_TTL` | `60s` | 预览结果缓存的有效期，`0` 表示禁用 |
| `RV_CACHE_MAX` | `64` | 缓存条目数上限 |
| `RV_AUDIT_LOG` | 空 | 审计日志文件路径，不配则只在内存里保留 |

**认证**：只有 `RV_USER` 和 `RV_PASSWORD` **都设置**才会启用。只设一个
不启用认证（避免半配置把所有人锁在外面）。启用后所有接口都需要
`Authorization: Basic ...`，浏览器会弹窗询问。

```bat
set RV_USER=viewer
set RV_PASSWORD=你的口令
set RV_TIMEOUT=90s
reportviewer.exe -addr :8090
```

**超时**：`RV_TIMEOUT` 接受 `90s` 这类时长写法，也接受纯数字（按秒算）。
超过时限的渲染会被中止，避免一个慢查询长期占着源库连接。

**审计日志**：设了 `RV_AUDIT_LOG` 后，每次预览都会记一行 JSON
（时间/用户/地址/模板/参数/状态/耗时），文件目录会自动创建：

```bat
set RV_AUDIT_LOG=D://ops//reportviewer//audit.log
```

不设这个变量就不会产生日志文件，但仍可通过 `GET /api/audit` 看到内存里
的最近记录。

**缓存**：同一模板同一参数的预览结果会缓存起来，重复请求直接返回，
不再重新渲染。响应头 `X-Cache: HIT|MISS` 可以看出是否命中，
`X-Render-Ms` 是本次实际渲染耗时（命中时为 0）。模板文件被修改后，
对应的缓存会自动失效。设 `RV_CACHE_TTL=0` 可关闭缓存。

### 3.4 数据源口令（按需）

程序会自动发现 webroot 里配置的所有数据连接。若报表需要查**非 FRDemo**
的库，必须注入口令。

**查看需要哪些变量**：启动程序 → 左下角点「数据源」→ 面板里每个标红
「缺密码」的连接会显示它需要的环境变量名。

命名规则：

| 连接名 | 环境变量 |
|---|---|
| `MESCS`（纯 ASCII） | `FINE_PWD_MESCS` |
| `气密检测77`（含中文） | `FINE_PWD_E6B094E5AF86E6A380E6B58B3737` |

中文连接名的变量名 = `FINE_PWD_` + 连接名 UTF-8 字节的十六进制（大写）。

设置示例（CMD）：

```bat
set FINE_PWD_MESCS=你的密码
reportviewer.exe -addr :8090
```

设置示例（PowerShell）：

```powershell
$env:FINE_PWD_MESCS = "你的密码"
.\reportviewer.exe -addr :8090
```

> 口令只存在进程环境变量里，**不落盘、不写日志、不返回给浏览器**。
> 修改后需重启程序。

## 4. 启动

### 4.1 前台运行（调试用）

```bash
./reportviewer.exe -addr :8090
```

启动成功会打印：

```
报表查看器已启动: http://127.0.0.1:8090
webroot:    D:\tomcat-win64\webapps\webroot
reportlets: D:\tomcat-win64\webapps\webroot\WEB-INF\reportlets
```

### 4.2 注册为 Windows 服务

用 [nssm](https://nssm.cc/)：

```bat
nssm install OpsWatchReportViewer "D:\ops\reportviewer.exe" "-addr :8090"
nssm set OpsWatchReportViewer AppEnvironmentExtra FINE_PWD_MESCS=你的密码
nssm set OpsWatchReportViewer DisplayName "报表查看器"
nssm set OpsWatchReportViewer Description "FineReport 模板离线查看器"
nssm start OpsWatchReportViewer
```

### 4.3 Linux 后台常驻

```bash
nohup ./reportviewer -addr :8090 >> /var/log/reportviewer.log 2>&1 &
```

> **坑**：SSH 断开可能杀掉后台进程。必须用 `nohup ... &`（或 `setsid`），
> 单纯 `./reportviewer &` 会在会话结束时被回收。

### 4.4 开机自启（Linux）

写 `/etc/systemd/system/reportviewer.service`：

```ini
[Unit]
Description=FineReport Report Viewer
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/reportviewer
ExecStart=/opt/reportviewer/reportviewer -addr :8090
Environment=FINE_PWD_MESCS=你的密码
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now reportviewer
```

## 5. 验证

启动后按顺序检查：

```bash
# 1. 模板列表（应返回模板总数，示例环境约 1770）
curl http://127.0.0.1:8090/api/templates

# 2. 连接状态（应看到 total / ready 两个数字）
curl http://127.0.0.1:8090/api/connections

# 3. 渲染一个模板（FRDemo 报表，应返回 sheets 数组）
curl "http://127.0.0.1:8090/api/preview?path=demo/basic/%E5%88%86%E7%BB%84%E7%BB%9F%E8%AE%A1.cpt"

# 4. 健康检查（应返回 status=ok 与各数据源状态）
curl http://127.0.0.1:8090/api/health
```

**开启了认证时**，每个请求都要带凭据：

```bat
curl -u viewer:你的口令 http://127.0.0.1:8090/api/health
```

浏览器打开首页，左侧应出现模板树。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报「FineReport webroot 不存在」 | 路径错或 FineReport 未部署 | 用 `-webroot` 显式指定 |
| 启动报「reportlets 目录不存在」 | webroot 对了但不是 FR 安装目录 | 确认 `<webroot>/WEB-INF/reportlets` 存在 |
| 模板列表为空 | reportlets 路径不对 | 用 `-reportlets` 指定 |
| 报表数据为空，提示「数据集不存在」 | 模板引用的数据集在本次渲染中未加载 | 看「渲染提示」面板的具体告警 |
| 提示「数据连接 X 未配置密码」 | 未设环境变量 | 按 3.3 设置并重启 |
| 提示「连接数据源 X 失败」 | 库不可达 / 口令错 / 端口被防火墙拦 | 先 `telnet IP 端口` 验证网络 |
| 页面能开但图表空白 | 该图表类型尚未实现或数据为空 | 看「渲染提示」面板 |
| 端口被占用 | 8090 已被占用 | 换 `-addr` |

## 7. 卸载

1. 停止服务（`nssm stop` / `systemctl stop` / 结束进程）
2. 删除 exe 目录
3. 如设置了环境变量，清理之

程序**不写任何持久化文件**，除自身 exe 外无残留。webroot 内的文件一律只读。
